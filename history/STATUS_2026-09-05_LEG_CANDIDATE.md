## Candidate changes and tests

`tools/build_mk2ks_mk3.py` protects the five typed XY operands in each imported main-animation 54 record from the generic overlapping pointer relocator. Negative X values had formed apparent pointers across a preceding token boundary; six coordinate bytes were incorrectly changed from FF to FE. The intermediate coordinate-only payload changed bytes `005B49`, `005B55`, `005B61`, `0074B9`, `0074C5`, `0074D1` (FE to FF). The latest payload also contains the own-jump correction below. Program chips and UI are unchanged. `tools/test_native_leggrab.py` has three passing conversion tests.

Native vertical jump was incorrectly holding the middle, extended-leg pose in the air and assigning the tucked pose to landing. Original MK3's jump driver skips the first pose on takeoff, plays middle/tucked, and lands middle/first. The original Kano middle frame has a 140-pixel lower bound; the tucked frame's bound is 111. This was the underlying reason the airborne leg-grab test caught Kano when the original game missed. `native_vertical_jump()` now exports `(middle,tucked,0,middle,first,0)` into each of the six own animation blocks, preserving MKII's native jump scheduler/physics. Three unit tests verify original layout, exact phases and bounded exported roots. Square-wave recovery was adjusted to select the middle pose at its new index, retaining the original move semantics.

The paired catch now writes `60h` to MKII's own push timer `010619D0`, as the original MKII throws do at `FF8B9570/FF8B9590`. The 46-field grab no longer activates the common body-separation velocities when its victim crosses Sonya. Intermediate `diagnostic_v43_leg_push_geometry_near` establishes the fix; original MK3 and candidate cached-part geometry and paired screenshots were compared. The earlier suspected wrong third Kano sprite was not an art error: it matches the original game's pose.
